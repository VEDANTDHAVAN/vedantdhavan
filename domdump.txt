class="shell"><div class="section-head"><p class="eyebrow">Engineering notes</p><h2 class="h2">Decisions worth writing down.</h2><p class="lede">Short notes on engineering decisions, each traceable to a specific repository. These summarise what the code does — they are not invented case studies.</p></div><div class="notes-grid"><article class="note"><span class="note-index">01</span><h3 class="note-title">Provider-agnostic coding agents</h3><p class="note-body">Binding an agent to one model provider means every provider change becomes a rewrite. MyPI resolves a backend through a provider registry (Groq, Vercel AI Gateway, Anthropic SDK, OpenAI-compatible), so adding a backend is a registration step rather than a change to the agent loop.</p><p class="note-source">Source: MyPI — src/providers/*, src/index.ts</p></article><article class="note"><span class="note-index">02</span><h3 class="note-title">Normalising tool calls across providers</h3><p class="note-body">Tool-calling schemas differ between providers. MyPI keeps a single tool registry (read, write, edit, delete, list, stats, find, search, grep, bash) and maps it per provider, so the loop has one contract to satisfy regardless of which model is answering.</p><p class="note-source">Source: MyPI — src/tools/index.ts</p></article><article class="note"><span class="note-index">03</span><h3 class="note-title">Bounding an agent loop</h3><p class="note-body">An agent loop that can keep requesting tools is an unbounded cost. Two limits apply: the turn budget (20 by default) and per-tool output caps — 2000 lines / 50KB for shell, 200 and 100 results for search and grep. A large tool result is truncated rather than allowed to consume the whole context.</p><p class="note-source">Source: MyPI — src/agent/loop.ts</p></article><article class="note"><span class="note-index">04</span><h3 class="note-title">Separating probabilistic interpretation from deterministic decisions</h3><p class="note-body">In Studio Lead Automation the model extracts typed fields from a free-text inquiry; it does not decide whether the lead qualifies. That decision is scored by deterministic Python rules (budget, deadline, project type, contact details) with visible thresholds. The same email always produces the same verdict, and the rule is readable by someone who does not write Python.</p><p class="note-source">Source: Studio Lead Automation — README qualification rules</p></article><article class="note"><span class="note-index">05</span><h3 class="note-title">Why hybrid retrieval beats embedding-only search</h3><p class="note-body">Engram fuses dense and sparse results with RRF instead of relying on embeddings alone. Dense retrieval handles paraphrase; sparse (BM25) handles exact terms. Storing temporal metadata alongside each memory makes time-aware questions answerable, which pure similarity search cannot do.</p><p class="note-source">Source: Engram — packages/providers, packages/retrieval</p></article><article class="note"><span class="note-index">06</span><h3 class="note-title">Context budgeting and artifact parking</h3><p class="note-body">Engram treats context as a budget. Large tool outputs are parked as restorable artifacts and inlined only on demand, so they stay available without paying their token cost on every turn of the conversation.</p><p class="note-source">Source: Engram — artifact mechanism</p></article><article class="note"><span class="note-index">07</span><h3 class="note-title">Measuring a model under distribution shift</h3><p class="note-body">The industrial vision platform reports clean-set accuracy (99.72%) and drifted-set accuracy (58.60–62.94%) side by side rather than only the headline number, and uses embedding drift distance as an early signal that the input distribution has moved — visible before accuracy has had time to fall.</p><p class="note-source">Source: industrial-ai-vision-platform — README results</p></article><article class="note"><span class="note-index">08</span><h3 class="note-title">Refusing to answer is a valid outcome</h3><p class="note-body">SentinelRAG classifies the domain, audits what was actually retrieved, and applies a domain-specific confidence threshold before generating. The thresholds differ by domain because the cost of a wrong answer does not. Failed retrievals and traces are persisted so each bad answer informs the next iteration.</p><p class="note-source">Source: auto-rag-guardrail — SentinelRAG agent chain</p></article><article class="note"><span class="note-index">09</span><h3 class="note-title">Holding the comparison constant</h3><p class="note-body">GraphRAG Benchmark runs the same question set and corpus through LLM-only, basic RAG and GraphRAG pipelines, so the pipeline is the only variable. Cost and token usage are measured alongside accuracy, because an accuracy gain has to be reported with what it costs.</p><p class="note-source">Source: graphrag-benchmark — README</p></article><article class="note"><span class="note-index">10</span><h3 class="note-title">Capturing structure, not pixels</h3><p class="note-body">RepliUI loads a page in Playwright at two widths (1440×900 and 390×844) and reduces the captured DOM and visual signals to a typed WebsiteSpec before generating. The model works from structure rather than a screenshot, and the self-repair loop is capped at three attempts so a stuck case terminates instead of looping.</p><p class="note-source">Source: RepliUI — README</p></article><article class="note"><span class="note-index">11</span><h3 class="note-title">Decoupling ingestion from delivery</h3><p class="note-body">The BSE Trades Dashboard pulls take up to 15 minutes, so nothing live can be built directly on the upstream feed. Ingestion runs as a BullMQ worker, persists to PostgreSQL, then publishes to Redis Pub/Sub; Socket.IO fans it out to the browser. Because the write happens before the publish, the live view and the stored history cannot disagree.</p><p class="note-source">Source: BSE-Trades-Dashboard — README architecture</p></article><article class="note"><span class="note-index">12</span><h3 class="note-title">Approval before irreversible action</h3><p class="note-body">SecureIntent Orchestrator interprets an email into a structured action plan and requires explicit approval before executing it. The interpretation is shown as a readable plan rather than acted on silently, so a misreading can be corrected before it costs anything.</p><p class="note-source">Source: SecureIntent-Orchestrator — README</p></article><article class="note"><span class="note-index">13</span><h3 class="note-title">A score you cannot defend is not a product</h3><p class="note-body">The fraud platform pairs every XGBoost risk score with a SHAP explanation, and tracks runs in MLflow. That makes the output contestable by the person being flagged and auditable later — and makes a model promotion decision reproducible from the run that produced the model.</p><p class="note-source">Source: TransactionFraud-Risk-Platform — README</p></article><article class="note"><span class="note-index">14</span><h3 class="note-title">Designing an experiment so the answer is worth having</h3><p class="note-body">The NIFTY event study fixes its development/OOS split at a fixed date in advance and performs no threshold or holding-period optimization. With only 53 events (38 development, 15 OOS), that restraint is the point: it is what keeps the out-of-sample period genuinely held out.</p><p class="note-source">Source: nifty-recovery-event-study — README</p></article><article class="note"><span class="note-index">15</span><h3 class="note-title">Choosing not to add a backend</h3><p class="note-body">Property Post Maker renders a 1080×1350 creative and exports it as a PNG entirely in the browser — no API, no database. For a task that is fundamentally a rendering problem, adding server infrastructure would be cost without benefit.</p><p class="note-source">Source: property-post-maker — README</p></article><article class="note"><span class="note-index">16</span><h3 class="note-title">Real-time collaboration is a persistence problem</h3><p class="note-body">VedLab persists each project rather than holding state only in memory, so a collaborator joining late still sees the full document. Real-time cursors and comments are a layer on top of that persisted state, not a replacement for it.</p><p class="note-source">Source: vedlab — README</p></article></div></div></section><section id="about" class="section"><div class="shell"><div class="portrait-frame" style="margin-bottom: 2.5rem;"><img class="portrait" alt="Vedant Dhavan" loading="eager" decoding="async" width="1748" height="1304" src="/images/pic.jpg"></div><div class="section-head"><p class="eyebrow">About</p><h2 class="h2">Building systems end to end.</h2></div><div class="about-grid"><div><p class="about-bio">Software Engineer passionate about building scalable products at the intersection of Full-Stack Development, AI/ML, and intelligent automation.
